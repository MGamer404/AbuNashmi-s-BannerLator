Reproduction steps1. Bannerlator 3.1.6, container-1: Display backend X11, Graphics driver System, Proton-10.0-4-arm64ec, 1280x800 2. Env: GALLIUM_DRIVER=zink, MESA_GL_VERSION_OVERRIDE=4.5 3. Games card -> Mewgenics -> LAUNCH WITH -> Raw .exe -> Launch 4. After 1-3 min RAM drops from 4.5 GB free to 1.8-2.2 GB (game IS loaded) but the image is corrupted from the start: large diagonal slabs, smooth green/white/tan gradients with hard diagonal edges and big black triangles. Looks like a framebuffer stride/tiling mismatch. 5. Wine's 2D/GDI stays perfectly sharp (e.g. the Fatal Error dialog) - only the GL surface is corrupted.
Already triedRenderer: Zink (Mali Vulkan) AND softpipe (pure CPU rasterizer) -> SAME corruption, identical shape (rules out the renderer/driver). Graphics driver: System and Wrapper-leegao -> same. Fast OpenGL: on and off (OpenGL card -> Fast -> Off) -> same. Display backend: X11 corrupted; Wayland fails earlier with 'Could not create window: No matching GL pixel format available' (Error 65542), compositor log shows '0 GPU frames from games'. Post-processing: Scaling=None, Sharpen(CAS)/HDR/Debanding off -> same. Fullscreen Mode Off/Fit -> same. Also injected a self cross-compiled Mesa (libgallium-26.3.0-devel.so: -Dplatforms=x11,wayland -Dglx=dri -Dgallium-drivers=zink,virgl,softpipe, plus libwayland-client.so.0 soname aliases + libexpat/libsync/libc++_shared) via repacked .wcp -> injection works (app shows Installed, container loads), corruption unchanged. Cross-check on a different app: Winlator 11.1 with Vortek + WineD3D -> black screen and the game never loads (only ~1.4 GB used), while Bannerlator+Zink does load it (2.3-2.7 GB) but renders corrupted. Compositor log (Bannerlator's own, /sdcard/Download/Wayland-logs/): gpu compositor renders on Mali-G925-Immortalis MC12 with the system Vulkan driver dmabuf formats: AR24 linear, XR24 linear, AB24 linear, XB24 linear dmabuf the compositor's driver (Mali-G925-Immortalis MC12) reports no importable qcom_compressed layout: game swapchains stay linear stats last 10 s: 21 frames on screen (2.1 fps) | 0 GPU frames from games Hypothesis: on this Mali device the hand-off between the GL surface and the Vulkan swapchain / linear buffer (see leegao 'WSI Woes on Mali') is not handling stride/tiling correctly. Note Mali has no Turnip (Adreno-only; PanVK does not support CSF/Immortalis), and the Fast OpenGL GLX route is documented as needing Turnip.
