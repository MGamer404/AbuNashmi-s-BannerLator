# Bannerlator 3.1.4

Run Windows apps and games on Android — no PC and no root required.

**3.1.4 makes OpenGL games several times faster, on every Wine version.** On X11, every OpenGL frame used to be finished on the GPU, copied back to the processor and redrawn as a picture. The new **Fast OpenGL** setting sends it straight to the screen through Vulkan instead, the same road DXVK games already take. It's on by default and picks the right method for your Wine version by itself, from Wine 9.5 to Proton 11, arm64ec and x86_64. Old DirectDraw and Direct3D 1–7 games speed up too. 3.1.4 also makes Wayland easier and faster: one driver choice, no tap to start a game, and DirectX 12 no longer held back.

- **Fast OpenGL:** OpenGL on X11 about 4 to 5 times faster, DirectDraw about 2 times, on every Wine version. No freedreno, just your Turnip driver.
- **One OpenGL card** in container and game settings: Fast, Show FPS and Vsync off.
- **Wayland:** one driver choice through the new adapter, no tap to start, tear-safe zero-copy, DirectX 12 uncapped.
- **Sync selector** (esync, ntsync, fsync, wineserver), **Android games** in the Games tab, and Linux Steam client **offline mode**.

# What's New — everything since 3.1.3

## ⚡ Fast OpenGL: OpenGL on X11 4 to 5 times faster, on every Wine version

On X11, Bannerlator's OpenGL used an old "draw into memory" route: for every frame, the processor waited for the GPU to finish, copied the picture back, and handed it to the X server as an image. The GPU and the processor took turns instead of working together.

Fast OpenGL sends each frame straight to the screen instead. **Zink**, which turns OpenGL into Vulkan, presents it through a Vulkan swapchain, exactly like DXVK games do. The app picks one of two methods for you:

- **Wine 11 / Proton 11 (arm64ec):** Wine's own EGL route, with a Mesa EGL library built for X11 that ships inside the app.
- **Every other Wine version** (Proton 10, Wine 9.5, every x86_64 layer and third-party layers): a new Mesa OpenGL library (GLX) that ships inside the app, and Bannerlator's X server now understands GLX, so it can hand frames to Vulkan instead of copying them.

Measured on the Pocket FIT, Fast OpenGL off → on, same container, a minute apart:

| Wine version | Method | OpenGL test | DirectDraw test |
|---|---|---|---|
| Wine 11 / Proton 11.0-2 (arm64ec) | EGL | 364 → **1239–1455 fps** | 351 → **1086 fps** |
| GE-Proton 10.0-34 (arm64ec) | GLX | 381 → **1906 fps** | 587 → **1300 fps** |
| Proton 11.0-2 (x86_64) | GLX | 390 → **1502 fps** | 571 → **1275 fps** |
| Wine 9.5 (x86-64) | GLX | 386 → **1989 fps** | 601 → **1148 fps** |

SGI's skyfly, a real OpenGL program, went from 706 to **2662 fps** on Wine 9.5. The Wine 11 DirectDraw figure is from the pre-release 2 tests, which ran with the GPU held at a lower clock.

- **Helps:** OpenGL games (Quake-engine games, Half-Life 1, KOTOR, Neverwinter Nights, Noita, Dominions 6 …) and old DirectDraw / Direct3D 1–7 games that run through WineD3D, **on X11**.
- **Doesn't change:** DXVK (Direct3D 8–11), VKD3D (Direct3D 12) and Vulkan games, which already took the fast road. We checked all four Wine versions above with Fast OpenGL off and on: Vulkan, DirectX 11 and DirectX 12 stayed within 2%.
- **No freedreno.** Some apps make OpenGL fast by adding freedreno, a second, OpenGL-only driver. Fast OpenGL runs on the Turnip you already picked, so OpenGL, DirectX and Vulkan share one driver and its fixes.
- **Faster, not fast-forward:** more frames per second means smoother motion, not a faster game. A few very old games tie their speed to the frame rate; cap those with the FPS limiter.
- **The first game start after updating** copies the OpenGL libraries (about 24 MB) from the APK into the app's own folder, once. ImageFS isn't touched.

> ✅ **Tested** on the Pocket FIT: the OpenGL and DirectDraw tests and SGI's skyfly and wave on all four Wine versions above, each checked by screenshot. The app picked the right method on each with nothing set by hand. ⚠️ A full commercial OpenGL game hasn't been run through the GLX method yet. Please report OpenGL games, with fps before and after.

## 🟦 One OpenGL card

Container settings (General) and each game's settings have one compact **OpenGL** card with a single **?**:

- **Fast**: the method above. On by default. Wayland is always on. Greyed out, with the reason, when the graphics driver can't do it.
- **Show FPS**: Mesa's own fps counter in the top-left corner of OpenGL games.
- **Vsync off**: lets OpenGL games run above the screen's refresh rate. Many older OpenGL games ask for vsync and otherwise lock to your refresh rate (144 fps on a 144 Hz screen).

In game settings each one is **Auto / On / Off**, where Auto follows the container. They apply when the game starts. Power users can force a method with `BANNER_X11_EGL=0` (off), `BANNER_X11_EGL=1` (EGL) or `BANNER_X11_GLX=1` (GLX) in the environment variables.

## 🧩 Wayland: one driver choice

Until now, Wayland needed two drivers: your normal one for the screen, and a separate Linux-style "Wayland driver" for the game. That second one had to come from a special build, and most community drivers didn't have one.

Bannerlator now ships a small **Wayland adapter**. It takes the ordinary AdrenoTools Turnip you already use on X11 and lets it draw Wayland games, so any community Turnip works.

- New containers and **New Container Defaults** start on it. Existing containers are left alone; to switch one, set **Advanced → Wayland game driver → Adapter (uses your graphics driver)**.
- On Wayland the container shows one **Graphics driver** pick. The game-driver choice moved under **Advanced**.
- If Qualcomm's own driver is picked on Wayland, the screen now uses a bundled Turnip automatically instead of failing.
- New game windows get keyboard focus by themselves, and when a window closes, focus moves to the next program window.

> ✅ **Tested:** DiRT Showdown and the AIO Graphics Test on the adapter with the player's own Turnip (Pocket FIT, Adreno 750). ⚠️ Mali, Xclipse and PowerVR through the adapter are untested.

## 👆 Wayland: no more tapping the screen to start a game

Some games sat paused on a black or frozen screen until you tapped it. Bannerlator now brings the game's window to the front the same way X11 always has, through Wine's own helper inside the container (`winhandler.exe`).

> ✅ **Tested:** DiRT Showdown starts on its own with no tap. X11 was re-checked and still works as before.

## 🖼️ Wayland: zero-copy without half-drawn frames, and no 144 fps cap

- **Zero-copy** (game pictures straight to the screen, no copy) could show a picture before the GPU had finished drawing it. The adapter now waits until each picture is finished. ✅ No torn frames and no speed lost in testing.
- **Every Wayland game was capped at the screen's refresh rate.** A compositor change meant for the Linux Steam client's gamescope held every frame until the screen let go of it. Wayland games are uncapped again: in the AIO test, Vulkan went from 144 to 529 fps and OpenGL from 144 to 262.
- **Old DirectDraw games no longer crash on Wayland.** Mesa's helper thread crashed outside Wine's view; Fast OpenGL turns that thread off. The DirectDraw test went from a crash to about 2,470 fps.

## 🚀 DirectX 12: no longer held back

We found a bug in the Turnip driver's Adreno code. When a game only wanted to *check* "has the GPU finished yet?", the driver made it *wait* until the GPU had finished. DirectX 12 (through VKD3D-Proton) makes that check every frame, so the processor and the GPU took turns.

- **On Wayland,** the adapter answers those checks instantly, so this works with any Turnip you pick: a small DirectX 12 test went from about **600 fps to over 4,000**.
- **On X11,** the fix is inside the driver itself: [Banners-Turnip](https://github.com/The412Banner/Banners-Turnip/releases) **r4 and later**. Switch to a current driver to get it. The same DirectX 12 demo ran about **3.8× faster on X11** and **5.9× faster on Wayland** with the fixed driver.
- Heavier games gain less, because the GPU is usually the limit there. Processor-heavy DirectX 12 games, and games at high frame rates, gain the most.

## 🔄 Sync selector

A row of pills under the compatibility layer: **esync**, **ntsync**, **fsync** or **wineserver**, per container and per game (games follow the container unless you change them). The app checks what each layer supports and greys out the rest. A **?** and glossary entries explain each one. The old WINEESYNC / WINEFSYNC environment-variable checkboxes are gone; existing settings carry over.

> 📦 **ntsync and the other choices are built for the v9 Proton layers.** Get them from the in-app download catalog, or from the release: [Proton v9 layers — GE-Proton 11.0-7.1 / 11.0-7 / 11.0-6 / 11.0-5 / 11.0-3 · Proton 11.0-2 / 11.0-1 · Proton-CachyOS · Proton 10.0-4 · GE-Proton 10.0-34 (arm64ec + x86_64)](https://github.com/The412Banner/proton-wine/releases/tag/build-bionic-layers-20260930-v9)

## 📱 Android games in the Games tab

**+** now asks what you're adding first: a Windows game, a folder of games, or an **Android game**. Android games are picked from the apps on your phone, get a green **ANDROID** badge, and launch directly, with no container. They live in their own place, so deleting a container never removes them.

## 🐧 Linux Steam client

Ported from DroidDeck:

- **Offline mode** per entry (needs one online sign-in first).
- **Deck mode:** a working performance overlay (MangoHud) drawn correctly over Big Picture; Steam starts with `-steamos3` like SteamOS; a game that minimized itself behind the Steam menu comes back on Resume (gamescope p4).
- **Cleaner start and exit:** black loading and closing screens with the Steam art, the Steam client shuts down properly when you stop the session, and an interrupted runtime update repairs itself.
- **Smoother:** faster file lookups for the Steam client, gamescope realtime queues and Xalia off by default, and the Steam menu chord and double-Back timing tuned.

## 🔧 Smaller

- **Contents → Installed → ⋮ → Set as default…** for drivers and components: set one for new containers, all existing containers, or their games, with Undo.
- **Compatibility layer cards show the installed versionCode** ("Installed · v9"), so two builds of the same layer can be told apart.
- **DirectAudio** can be picked on **GE-Proton 11.0-7 and 11.0-7.1** (it was greyed out).
- **Controllers:** pad input reaches games faster (the input wait drops from up to 16 ms to at most 2 ms), and the app asks Android for unbuffered input.
- **Exit reports** now say which process exited and why (signal or exit code), and keep its last 400 log lines.
- The Wayland slide deck gained a results slide.

## ⚠️ Carried over — still open

- **Fast OpenGL:**
  - **32-bit OpenGL games on older 32-bit-only Wine setups** aren't covered; the OpenGL libraries are 64-bit only. Those games run as before.
  - **Games that draw OpenGL into child windows** haven't been tested on the GLX method; the X server's window-compositing support is basic. If one shows a black or frozen area, turn **Fast** off for that game.
- **Wayland:**
  - **Noita on Wayland closed once** after a graphics-buffer error (Android's file-handle safety check stopped it). It hasn't happened again since.
  - In the AIO Graphics Test's normal sweep, every API except Direct3D 11 is copied back to the processor to be shown inside the test's own window, which caps those rows around twice the screen refresh. That's the test, not the API: run each API on its own (`--cube <api> --bench 15`) for real numbers.
  - Mali, Xclipse and PowerVR through the adapter need testers.
- Everything listed as open in 3.1.3 is unchanged: the Linux Steam client items (FlatOut after Resume, Team Fortress 2 "insecure", Guide pressed twice after sleep, the proot patches' A/B), the Fusion HUD's GPU usage with **Lock GPU to max clock**, and BannerHub signing Steam out of SteamLite games.
