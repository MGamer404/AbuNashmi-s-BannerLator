# Bannerlator 3.1.7

Run Windows apps and games on Android — no PC and no root required.

**3.1.7 adds an Xbox / PC Game Pass store with cloud streaming, finishes the Deck style, and replaces how controllers reach your games.** Sign in with your Microsoft account, then download the PC games you own or have on Game Pass and play them with a licensed launch — or **stream** them, console-only games included, with optional frame generation. The console-style **Deck** interface now covers every screen and every setting. Controller input runs on **BANNERIN**, written from scratch for Bannerlator: sticks stop the moment you let go, XInput games can read the pad directly, and controller settings change while the game runs. Windows components can be **removed** again, recommendations look at what a game really uses, and the new **v15** layers bring 144 Hz back to the newest Wine builds.

- **Xbox / PC Game Pass store:** sign in, browse your library and Game Pass, download, add to your games and play — with cloud saves and your gamertag.
- **Xbox Cloud Gaming:** stream Game Pass games, console-only ones too, with the store's sign-in; an optional native player adds frame generation.
- **Deck style, complete:** every screen, every setting and the in-game menus, made for controllers; the XMB is back, full screen.
- **BANNERIN controllers:** sticks stop when you let go, Direct XInput with rumble, controller settings in game, DirectInput vibration.
- **Windows components:** a Deck page, **Remove** (puts back what an install changed), recommendations from what the game really uses, and Wine Mono installs again.
- **Steam:** switch between saved accounts, extra library folders, sort by Steam rating, and Goldberg fixes — from community contributor **MGamer404**.

# What's New — everything since 3.1.6

## 🟩 Xbox / PC Game Pass store

A fifth store, next to Steam, GOG, Epic and Amazon. Games are **downloaded and run on your device**.

- **Sign in** with your Microsoft account on Microsoft's own page. The app shows your **gamertag**, never your sign-in email, and keeps the account out of logs.
- **Library:** the PC games you own plus **PC Game Pass** titles (with a Game Pass badge and filter), on art-shaped cards.
- **Downloads** use several connections across all of Microsoft's download servers, split big files into chunks, show speed and time left, and **resume** after an app update. Library cards show *Downloading N%*.
- **Add to games** with the usual container picker; the card gets an **XBOX** label.
- **Licensed launch:** every launch checks your license with Microsoft and starts the game's own program — no Xbox app. The Xbox runtime the games talk to (sign-in, saves, store checks) is installed into the container for the session and put back afterwards.
- **What games need is set up for you:** the Visual C++ runtime a game declares is installed before its first launch — in arm64ec containers also Microsoft's **ARM64** Visual C++ 2015–2022 runtime when a game asks for it (*Valor Mortis*); the Windows Runtime classes Xbox sign-in needs are registered; Proton 10 containers get the sign-in pieces they lack.
- **Saves:** a game's saves stay in the container, the **Save Manager** backs them up on exit, and **cloud saves** sync while you play and when you leave the game — from its own Quit or from the side menu (switch in the Xbox tab's settings, off by default).
- **Games that ship Microsoft's own Xbox runtime** (Cyberpunk 2077) use the app's instead, which works without Windows' Gaming Services. A per-game switch, **Use the app's Xbox runtime** (on by default), appears only for those games.

> ✅ **Device-tested** on the Pocket FIT: sign-in and gamertag; library (26 owned + 723 Game Pass, 437 with a PC version); owned and Game Pass downloads incl. resume after an app update; *A Game About Digging A Hole* (78 fps), *BALL x PIT* (225 fps, cloud saves uploaded on both ways of quitting), *Brotato* (427 fps) and *High On Life* (title screen, 171 fps) run; *Cyberpunk 2077* reaches its main menu (~100 fps, D3D12); *Valor Mortis* gets its ARM64 runtime and reaches its shader-compilation screen.

> ⏳ **First launch of a game with cloud saves** can sit on its loading screen for a long while — the game is downloading your saves (Cyberpunk 2077: about 6 minutes here, others report 20–30). Leave the game in front: Android pauses a game in the background. Later launches are quick.

## ☁️ Xbox Cloud Gaming

Play Game Pass games streamed from Microsoft's servers instead of downloading them — including console games that have no PC version.

- **In the Xbox library:** every game you can stream has a **Cloud** badge, console-only games say **Cloud only**, and a **Cloud** filter shows just those. A game page offers **Stream** next to **Install** (or on its own for a cloud-only game).
- **One sign-in:** streams use the store's Microsoft sign-in. Nothing to sign in to again, and the streaming tokens stay inside the app.
- **Bannerlator's own player** runs the stream with your controller (rumble included). **Guide** once opens the Xbox menu; twice (or held) opens the player's own menu.
- **Player settings** (Xbox tab › Profile › **Cloud gaming settings**, and in the player's menu): resolution (phone, PC or TV profile — the PC profile gave 2560×1440 on the Pocket FIT), server region, game language, video quality, a bitrate limit and *Stop quality drops*; picture effects (brightness, contrast, gamma, saturation, sharpening, deband, FXAA, CRT, NTSC, Toon) that share their profiles with the Wine games' screen effects; a performance overlay, volume and rumble. Settings that only apply when a stream starts offer *Restart the stream with these settings*.
- **In Games before you install:** a streamable Xbox game can be added to Games and streamed from there. **Download** later completes the same entry, which then launches the installed game. Xbox shortcuts can launch the installed game (**Raw**) or **Stream** it.
- **Microsoft's own web player** (xbox.com/play) is still there, behind the cloud button in the Xbox store's header (or its menu). It needs its own Microsoft sign-in.

### Native player with frame generation (experimental, opt-in)

**Cloud gaming settings › Player engine › Native (frame gen)** (Android 10 and newer) plays the stream with Google's WebRTC library and Bannerlator's own Vulkan compositor instead of a web page, so frame generation can add frames to the 60 fps stream.

- **Frame generation:** **Win-FG 2×**, or **LSFG 2× / 3× / 4×** with the `Lossless.dll` you imported in Settings (the same one Wine games use). A **frame-rate target** (the screen's rate, 30–165 fps, or any value with a slider) sets what you see.
- **Low latency switches:** instant controller input (each press sent at once instead of every 16 ms), a small network buffer, the video chip's low-latency decoder mode, and a **zero-copy** picture (frames go straight from the video chip to the screen, used while frame generation is off). Zero-copy and frame generation switch live, mid-stream.
- **Leaving the player:** a short trip to another app keeps the stream. After 45 seconds away, the session is closed cleanly and the player offers to restart it when you come back, instead of showing a dead stream.
- The web engine stays the default, and the native player falls back to it if it can't start. Picture effects and the overlay levels apply to the web engine.

> ✅ **Device-tested** on the Pocket FIT: *BALL x PIT* and *SpeedRunners 2* streamed in our player with the controller (SpeedRunners 2 then downloaded from the same Games entry and launched installed); *GRID Legends* in Microsoft's web player. Native player: 2560×1440 at 60 fps, Win-FG and LSFG 2× 59 → 119 fps, zero-copy picture delay about 17 ms, frame generation switched Off / Win-FG / LSFG in any order mid-stream without a crash.

## 🎮 The full Deck style

The Deck style is a console-style interface, made to be driven with a controller. It existed as a preview; 3.1.7 makes it complete.

- **Landscape:** main tabs down the left side, a slim title line and a button-hint bar (L1/R1 tabs, A select, B back, X options, Y search). Android's navigation bar stays hidden, also behind pop-ups and sheets. **Portrait:** a phone layout with tabs along the bottom.
- **Home** with a hero banner for the game you played last, shelves and library views; **game pages** with play time, launches, storage and the full game menu.
- **Settings editor** for every container, every game and the defaults for new containers: Simple, Advanced and Expert levels, search, an *Inherits from* chain (All containers › container › this game), an Unsaved-changes bar and per-row reset. **Every setting is edited in place** — DXVK/VKD3D, the DX wrapper, the X11 driver, Wayland (incl. Mali PanVK), drives, audio, ReShade, env vars, the Linux runtime and the rest; nothing opens a Classic screen any more. The Steam (Linux) client has its own page and never shows Wine-only options.
- **In-game menus:** a game menu (Back, or a four-finger tap) and a quick menu (the Menu button), every page driven with the controller.
- **Fits every screen:** the console layout works at the stock and large display sizes, draws 20% smaller than Classic and keeps clear of a camera hole.
- **The XMB** is back as a Shelf library view, **full screen**, with a game's settings in its own columns.
- **Add games, game details, drive C and Change exe** open over Deck instead of Classic's Games screen. First-run setup appears only on a fresh install.

## 🕹️ BANNERIN — new controller input

The way the app hands controller input to Wine has been replaced with **BANNERIN**, written from scratch in Rust for Bannerlator.

- **Sticks stop when you let go.** Stick updates follow the game's own frame rate (at most 60 a second by default), so a game that reads input slowly never falls behind. Buttons are never delayed.
- **Idle controllers no longer wake the CPU**, and games list only the controllers you actually have (before, four were always shown).
- **Direct XInput:** XInput games read the controller straight from BANNERIN — 32-bit, 64-bit and ARM64X — with rumble on **Both** motors or a **Single** one (the default on the AYANEO Pocket FIT). **On for new containers**; existing containers keep their setting.
- **Controller settings in game** (Controls › Pad): controller type (Generic, Xbox 360 / One / Series, a classic DirectInput pad, and experimentally DualShock 4, DualSense, Switch Pro, Joy-Con pair, Steam Deck), XInput source, DirectInput visibility and stick updates — without restarting the game. Saved per game or per container.
- **DirectInput vibration:** DirectInput games can now vibrate the controller (constant force, ramp and the periodic effects, mixed into the two motors; steady forces fade after about 2 seconds). On by default.
- **A game's own XInput DLL** (Dark Souls Remastered and others) is handled automatically.
- **Controller input log:** Log Manager › *Controller input* writes a pass/fail checklist per player (`controller.txt`) to send when a game's controls don't work. Off by default.

## 🧩 Windows components

- **A Windows components page in Deck** for a game, a container or the defaults: *Recommended for this game*, *Optional*, every component with search, and Wine's or Microsoft's DLLs for Direct3D, DirectSound, XAudio and the rest.
- **Remove:** every install now records what it changed — files placed, originals replaced, folders and registry values. **Remove** puts the originals back and deletes only what the component added. Components installed before 3.1.7 can be removed when they have a Windows Installer product; otherwise **Reinstall** once to make them removable.
- **Smarter recommendations**, strongest evidence first: what the game's store lists (Steam, GOG, Epic, Amazon), the game's Steam install script, then the DLLs its exe actually loads. Installers nothing confirms move to a folded *Also in the game's folder* group. *DiRT Showdown* went from eight suggestions to the DirectX pieces and OpenAL it really uses.
- **Wine Mono installs again:** every Mono entry failed with *the package installs nothing here*. They now install without opening the container, including Mono's Windows support package (the .NET folders and registry entries .NET programs look for). **mono-10.4.1** now really is Wine Mono 10.4.1 (it downloaded 10.1.0 before), and installing a Mono over an older one clears the old version's leftover files — **Remove** puts them back.
- **ARM64 Visual C++ 2015–2022** is a new catalog component (by **MGamer404**), used by the Xbox store for arm64ec containers.

> ✅ **Device-tested** on the Pocket FIT: Wine Mono 10.4.1 installed into a container that had 10.1.0 — all 2,949 files and the registry in place, the two leftover files of 10.1.0 removed on a reinstall, no crash. A .NET program has not been run on it yet.

## 🚂 Steam

- **Switch between saved Steam accounts** without signing in again, by profile name (#615).
- **Extra library folders:** install Steam games into additional folders in the normal Steam layout; games imported from another client keep that client's files on uninstall (#616).
- **Search and sort your Steam library by Steam rating** (#617).
- **Goldberg:** no more black screens, errors are shown, and switching back to real Steam works (#613). Steam Cloud sync during Goldberg launches is a setting, on by default (#614).
- **Headless Steam** accepts Valve's Steam build 1791918634, checks itself before use, and reads the client's zip correctly.

## 💾 Save backups that include emulator saves

Many Steam emulators keep saves outside your user folder, so backups never had them. **Container backups** now also take `ProgramData/Steam/<name>/<app id>`, `Users/Public/Documents/Steam/…`, OnlineFix and EMPRESS folders; **a game's backups** (incl. the automatic one after a session) take that game's emulator folders, found by its Steam app id. Restore puts them back.

## 📦 New compatibility layers — versionCode 15

Six layers are rebuilt at **versionCode 15** and are in the catalog: **Proton 10.0-4**, **GE-Proton 10.0-34**, **Proton 11.0-1**, **Proton 11.0-2**, **GE-Proton 11.0-9** and, new, **DroidDeck-Proton 11.0-11.1**, which replaces 11.0-9.1 (x86_64 builds of 11.0-2, GE 11.0-9 and DroidDeck 11.0-11.1 too). Release notes: [bionic layers v15](https://github.com/The412Banner/proton-wine/releases/tag/build-bionic-layers-20261023-v15).

- **FEX's unixlib loads again** on GE-Proton 11.0-9 and DroidDeck-Proton (the drawer showed *N/A*).
- **Windows Runtime classes in both halves of the prefix**, so 64-bit games find the newer ones (Xbox sign-in among them).
- **Fixes from GameNative:** the full resolution list in virtual-desktop mode, .NET / MonoMod mods no longer crashing on arm64ec, memory-layout and crypt32 fixes, and more.
- They install into a new `-15` slot next to the old ones; a container on an older build of the same layer is offered **Update layer → v15** with a revert snapshot.

Two app changes go with them:

- **144 Hz on GE-Proton 11.0-9 and DroidDeck-Proton:** Valve's newer Wine reads the app's refresh-rate unlock the other way round, which capped these layers at 60 Hz. 3.1.7 recognises the newer Wine and writes the setting its way.
- **DroidDeck-Proton is one line:** a container on DroidDeck-Proton 11.0-9.1 is now offered **Update layer → 11.0-11.1** (the updater only matched identical version names before).

> ✅ **Device-tested** on the Pocket FIT: DroidDeck-Proton 11.0-11.1 arm64ec — FEX's unixlib loaded, *BALL x PIT* runs, and a container updated in place from 11.0-9.1 kept its saves and ran *DiRT Showdown* at 143.7 fps on the 144 Hz screen. The other five layers are built from the same sources but were not launched on the device.

## 🌊 Wayland

- **The bundled Wayland adapter is the default** whenever the container's graphics driver can carry it. The driver cog becomes **adapter settings**: a profile (Auto, Smooth, Fast, Compatibility) plus Advanced switches for present mode, asynchronous copy, zero-copy, render fences, UBWC, DRM modifiers, the KGSL timing fix and **Subgroups**, each explained in a line.
- **Smoother frames under GPU load:** the compositor's copy path no longer waits for the GPU on its only thread (34–86 ms stalls measured on an Adreno 6xx, 3–12 ms on the Pocket FIT), and zero-copy frames carry the game's own render fence, so they no longer reach the screen half drawn on older Adreno kernels.
- **Native Vulkan games:** subgroup support is passed through on Mesa drivers and BGRA formats are offered to native Vulkan programs — *DOOM Eternal* no longer quits on start or shows a black screen with zero-copy.
- **No clipboard notice:** Wayland games read your phone's clipboard only when you paste inside the game.

## 🔊 DirectAudio

- **Support is detected from the layer's files** instead of a fixed list, so new layers that ship the driver are no longer greyed out.
- **Driver 1.4.0** bundled; at launch the newest build wins — a layer's own newer driver is kept, an older one is upgraded.

> ✅ **Device-tested** on the Pocket FIT: *BALL x PIT* on Proton 11.0-9.1 with DirectAudio, the layer's driver upgraded 1.3.2 → 1.4.0.

## 🈶 Chinese, Japanese and Korean text

Games that use a Chinese, Japanese or Korean code page (GBK, Shift-JIS…) showed garbled text: Android always answers *C.UTF-8* when Wine asks for the language, so Wine fell back to English and code page 1252. Bannerlator now hands Wine the language from the **LC_ALL** setting of the container (or the game) — for example `zh_CN.UTF-8`. `LOCALE_FIX_DISABLE=1` in the env vars turns it off.

> 🧪 **Not yet tested with a game.** The fix itself was checked on the device (C.UTF-8 → zh_CN.UTF-8); please tell us how your CJK games look.

## 📂 Open with → Bannerlator

Long-press a Windows **.exe** in any file manager and choose **Open with › Bannerlator**: pick the container, then **Play from library** (when the container already has the game), **Add to library and run**, or **Run once**.

## ⬇️ Small updates

3.1.6 introduced small updates; 3.1.7 is the first stable release that uses them. On 3.1.6 or a 3.1.7 test build the in-app updater downloads a patch instead of the whole app, rebuilds the new app from the installed one, checks it is an exact copy of the release and installs it as a normal update. If anything goes wrong it falls back to the full download.

## 🛠️ Fixes

- **Smoother Games screen and side menu:** store art was saved and loaded at full size (Xbox posters are 1440×2160), which overflowed Android's image cache, so the grid and the side menu stuttered (73 ms frames measured). Covers and tile pictures are now kept at most 1200 px on their long side. Measured on the Pocket FIT: 0 late frames.
- **Xbox games crashed at start** (Cyberpunk 2077's crash reporter closed it at once): the ARM64X build of BANNERIN's XInput DLL ran its ARM-only start-up code as PC code on every thread start. It now has none.
- **On-screen controller:** it takes its player slot before Wine starts, so games that look for controllers only at startup (*Ender Lilies*, *Dark Souls III*, *Ninja Gaiden Sigma*, *Toy Story 2*) see it.
- **DirectInput "visible"** writes no registry entry again, as the old *Exclusive Input off* did — *Watch Dogs 2*'s controls work again.
- **winhandler.exe / wfm.exe** are put back whenever a container's copy differs from the app's, so the *Toy Story 2* black-screen fix can't be undone by a container update.
- **Unsaved edits:** the container editor and a game's settings ask *Save / Discard / Keep editing* instead of dropping your changes on Back.
- **Frame generation:** the interpolation-model list offers Win-FG's two real models (optical flow, bidirectional) instead of five entries.
- **Win-FG** could crash when it was switched off and on again in the same session; fixed (found in the cloud player, the same code serves Wine games).
- **Settings:** the MIDI SoundFont choice is saved and used for new containers. The VEGAS stock-config download sheet now opens.
- Saving DirectAudio's fine-tune no longer switches the DirectAudio microphone off.
- **Classic, Linux client:** the Steam (Linux) tile and its in-game drawer no longer offer Wine-only actions.
- The side menu closes with Back and a tap beside it on every screen.
- New containers get **AIO Graphics Test 2.2.0** and a Cursor Test in drive C.

## ⚠️ Carried over — still open

- **Xbox:** *Forza Horizon 5* does not start (its anti-tamper closes the game after the splash). The download notification updates too often (Android drops some updates). Some games need a long first launch while cloud saves download (see above). *Valor Mortis* was not played past its shader compilation.
- **Xbox Cloud Gaming:** touch controls have not been tried; the native player is experimental. The Win-FG fix has not been re-tested in a Wine game.
- **Steam (MGamer404's changes):** switching between two saved accounts and a Goldberg *Cold Client* shortcut have not been device-tested yet.
- **Download Manager:** uninstalling a Steam game from its game page, or moving it, leaves its row in the library list until the list refreshes.
- **Logs:** Epic, GOG and Amazon user names are hidden by pattern only (the Steam and Xbox stores register theirs).
- **Chinese / Japanese / Korean text:** not yet tested with a game (see above).
- **Wine Mono:** a .NET program has not been run on a Mono installed this way yet. Mono's setup steps that need its own code (Wine's placeholder .NET files) can't run outside the container.
- **v15 layers:** only DroidDeck-Proton 11.0-11.1 was launched on the device.
- **Deck style:** broadly reworked — please report anything that looks or navigates wrong, with a screenshot.
- **BANNERIN:** if a controller misbehaves in a game, please report it with the game and the controller type. On Wine 9.5 and other older Wine builds, Game Controllers' DInput tab can't play effects (that Wine's control panel; games are not affected).
- **Windows components:** Steam games you added yourself but don't own can't be looked up on Steam yet; GOG and Epic games installed before 3.1.7 have no saved dependency list.
- Everything listed as open in 3.1.6 is unchanged.
