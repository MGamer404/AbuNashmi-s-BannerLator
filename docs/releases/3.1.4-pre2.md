# Bannerlator 3.1.4 — pre-release 2

Run Windows apps and games on Android — no PC and no root required.

**Pre-release 2 of 3.1.4 makes OpenGL games on X11 several times faster.** On X11, every OpenGL frame used to be finished on the GPU, copied back to the processor and redrawn as a picture. The new **Fast OpenGL** setting sends it straight to the screen through Vulkan instead, the same road DXVK games already take. Old DirectDraw and Direct3D games that run through WineD3D speed up too.

- **Fast OpenGL** (on by default): OpenGL on X11 about 3 to 6 times faster in our tests.
- **One OpenGL card** in container and game settings: Fast, Show FPS (Mesa's counter in the corner) and Vsync off.
- **Sync selector:** esync, ntsync, fsync or wineserver, per container and per game.
- **Add Android games** to the Games tab, launched without a container.
- **Linux Steam client:** offline mode, a working Deck-mode performance overlay, cleaner start and exit.

Everything from pre-release 1 is here too.

# What's New — since pre-release 1

## ⚡ Fast OpenGL: OpenGL on X11 up to 5× faster

On X11, Bannerlator's OpenGL went through an old "draw into memory" route: for every frame, the processor waited for the GPU to finish, copied the picture back, and handed it to the X server as an image. The GPU and the processor took turns instead of working together.

Fast OpenGL switches on Wine's own EGL route and a Mesa OpenGL library built for X11 (it ships inside the app). Zink, which turns OpenGL into Vulkan, then presents each frame straight through a Vulkan swapchain, exactly like DXVK games do.

Measured on the Pocket FIT (same device, back-to-back, Fast off → on):

| Test | Off | On |
|---|---|---|
| OpenGL test cube | 222 fps | **1250 fps** |
| SGI skyfly (classic OpenGL program) | 362 fps | **1062 fps** |
| SGI wave | 241 fps | **782 fps** |
| DirectDraw cube (WineD3D on OpenGL) | 351 fps | **1086 fps** |

- **Helps:** OpenGL games (Quake engine games, Half-Life 1, KOTOR, Neverwinter Nights, Noita, Dominions 6 …) and old DirectDraw / Direct3D 1–7 games that run through WineD3D, **on X11**.
- **Doesn't change:** DXVK (Direct3D 8–11), VKD3D (Direct3D 12) and Vulkan games, which already take the fast road, and Wayland, which always did.
- **Faster, not fast-forward:** more frames per second means smoother motion, not a faster game. A few very old games tie their speed to the frame rate; cap those with the FPS limiter.

> ✅ **Tested:** the four programs above on the Pocket FIT, images identical with Fast on and off. ⚠️ Not yet tested with a full commercial OpenGL game on X11; Half-Life is the next one. Please report OpenGL games, with fps before and after.

## 🟦 One OpenGL card

Container settings (General) and each game's settings now have one compact **OpenGL** card with a single **?**:

- **Fast**: the new path above. On by default; Wayland is always on; greyed out with the reason when the driver or layer can't do it.
- **Show FPS**: Mesa's own fps counter in the top-left corner of OpenGL games.
- **Vsync off**: lets OpenGL games run above the screen's refresh rate. Many older OpenGL games ask for vsync and otherwise lock to your refresh rate (144 fps on a 144 Hz screen).

In game settings each one is **Auto / On / Off**, where Auto follows the container. They apply when the game starts.

## 🔄 Sync selector

A row of pills under the compatibility layer: **esync**, **ntsync**, **fsync** or **wineserver**, per container and per game (games follow the container unless you change them). The app checks what each layer supports and greys out the rest. A **?** and glossary entries explain each one. The old WINEESYNC / WINEFSYNC environment-variable checkboxes are gone; existing settings carry over.

## 📱 Android games in the Games tab

**+** now asks what you're adding first: a Windows game, a folder of games, or an **Android game**. Android games are picked from the apps on your phone, get a green **ANDROID** badge, and launch directly, with no container. They live in their own place, so deleting a container never removes them.

## 🧰 Smaller

- **Contents → Installed → ⋮ → Set as default…** for drivers and components: set one for new containers, all existing containers, or their games, with Undo.
- **Compatibility layer cards show the installed versionCode** ("Installed · v9"), so two builds of the same layer can be told apart.
- **DirectAudio** can be picked on **GE-Proton 11.0-7 and 11.0-7.1** (it was greyed out).
- **Controllers:** pad input reaches games faster (the input wait drops from up to 16 ms to at most 2 ms), and the app asks Android for unbuffered input.
- **Exit reports** now say which process exited and why (signal or exit code), and keep its last 400 log lines.

## 🐧 Linux Steam client

Ported from DroidDeck:

- **Offline mode** per entry (needs one online sign-in first).
- **Deck mode:** a working performance overlay (MangoHud) drawn correctly over Big Picture; Steam starts with `-steamos3` like SteamOS; a game that minimized itself behind the Steam menu comes back on Resume (gamescope p4).
- **Cleaner start and exit:** black loading and closing screens with the Steam art, the Steam client shuts down properly when you stop the session, and an interrupted runtime update repairs itself.
- **Smoother:** faster file lookups for the Steam client, gamescope realtime queues and Xalia off by default, and the Steam menu chord and double-Back timing tuned.

## 🧪 Drivers

The Turnip "check, don't wait" fix from pre-release 1 (DirectX 12 uncapped) is now inside [Banners-Turnip](https://github.com/The412Banner/Banners-Turnip/releases) **r4 and later**, so X11 gets it too by switching to a current driver.

## ⚠️ Still open

- **Noita on Wayland closed once** after a graphics-buffer error (Android's file-handle safety check stopped it). It's being investigated and hasn't happened again since.
- **Fast OpenGL on Proton 10 (X11):** not available; those layers don't have Wine's EGL switch. Wayland is unaffected.
- **AIO Graphics Test:** in its normal sweep, every API except Direct3D 11 is copied back to the processor to be shown inside the test's own window, which caps those rows around twice the screen refresh. That's the test, not the API: run each API on its own (`--cube <api> --bench 15`) for real numbers.
- Everything still open in pre-release 1 and 3.1.3 is unchanged.
