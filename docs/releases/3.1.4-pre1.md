# Bannerlator 3.1.4 — pre-release 1

Run Windows apps and games on Android — no PC and no root required.

**Pre-release 1 of 3.1.4 makes the Wayland display mode much easier to use, and much faster in DirectX 12.** Wayland now runs your games on the same Turnip driver you already pick for X11: one driver choice, no separate "Wayland driver" to find. Games start without tapping the screen, the fast zero-copy mode no longer shows half-drawn frames, and DirectX 12 is no longer held back by a driver bug that made the processor wait for the GPU every frame.

- **One driver choice:** new containers use the built-in **Wayland adapter**, which runs your normal community Turnip driver.
- **No tap to start:** games come to the front by themselves, the same way they do on X11.
- **Tear-safe zero-copy:** each picture is shown only once it is fully drawn.
- **DirectX 12 is uncapped:** a small DirectX 12 test went from about 600 fps to over 4,000 fps on Wayland.

X11 is not changed in this pre-release. Everything from 3.1.3 is here too.

<details>
<summary><b>📖 Switching an existing container to the Wayland adapter</b> (tap to expand)</summary>

1. Open the container's settings and set the display to **Wayland**.
2. Pick your usual Turnip in **Graphics driver**. On Wayland that one choice now drives both the screen and the game.
3. Open **Advanced → Wayland game driver** and choose **Adapter (uses your graphics driver)**.
4. Launch a game. With the DXVK HUD on, the GPU name reads **Wrapper(Adreno …)**, which means the adapter is in use.

The older choices (**Auto (by GPU)**, the bundled Wayland Turnips, and imported Wayland drivers) are all still in that list if you want them. Shortcuts can override it the same way, under their own Advanced section.

# What's New — everything since 3.1.3

## 🧩 One driver choice on Wayland

Until now, Wayland needed two drivers: your normal one for the screen, and a separate Linux-style "Wayland driver" for the game. That second one had to come from a special build, and most community drivers didn't have one.

Bannerlator now ships a small **Wayland adapter**. It takes the ordinary AdrenoTools Turnip you already use on X11 and lets it draw Wayland games, so any community Turnip works.

- New containers and **New Container Defaults** start on it. Existing containers are left alone.
- On Wayland the container shows one **Graphics driver** pick. The game-driver choice moved under **Advanced**.
- If Qualcomm's own driver is picked on Wayland, the screen now uses a bundled Turnip automatically instead of failing.
- New game windows get keyboard focus by themselves, and when a window closes, focus moves to the next program window.

> ✅ **Tested:** DiRT Showdown and the AIO Graphics Test ran on the adapter with the player's own Turnip (AYANEO Pocket FIT, Adreno 750); the DXVK HUD read "Wrapper(Adreno (TM) 750)". ⚠️ Other games and other GPUs are untested.

## 👆 No more tapping the screen to start a game

On Wayland, some games sat paused on a black or frozen screen until you tapped it. Windows only treats a game as "active" once it has been brought to the front, and on Wayland nothing was doing that.

Bannerlator now brings the game's window to the front the same way X11 always has: it asks Wine's own helper inside the container (`winhandler.exe`) to raise the window, once when it appears and once more a second later.

> ✅ **Tested:** DiRT Showdown starts on its own with no tap; its splash screen and main window were both raised, and the old slow "paused" phase is gone. X11 was re-checked and still works as before.

## 🖼️ Zero-copy without half-drawn frames

Zero-copy is the fast Wayland mode where the game's pictures go straight to the screen with no copy in between. It could show a picture before the GPU had finished drawing it, which can look like flicker or tearing. The adapter now waits until each picture is finished before showing it, and it prefers pictures the screen has already let go of, so it doesn't stall waiting for one.

> ✅ **Tested** on the Pocket FIT with zero-copy on: no torn frames and no speed lost in the AIO Graphics Test.

## 🚀 DirectX 12 on Wayland: no longer held back

We found a bug in the Turnip driver's Adreno code. When a game only wanted to *check* "has the GPU finished yet?", the driver instead made it *wait* until the GPU had finished. DirectX 12 (through VKD3D-Proton) makes that check on every frame, so the processor and the GPU ended up taking turns instead of working at the same time.

The Wayland adapter now answers those checks instantly, so this works with any Turnip you pick, even one that still has the bug.

- A small DirectX 12 test scene: about **600 fps → over 4,000 fps** on Wayland.
- Heavier games gain less, because the GPU is usually the limit there, not this wait. Processor-heavy DirectX 12 games, and games at high frame rates, should gain the most.
- **X11 isn't changed by this app update.** The same bug is fixed inside the driver itself in [Banners-Turnip](https://github.com/The412Banner/Banners-Turnip), and the next driver release brings the fix to X11 too. In testing, the fixed driver made the same DirectX 12 demo about **3.8× faster on X11** and **5.9× faster on Wayland**.

> ✅ **Tested:** the adapter fix on the Pocket FIT with the DirectX 12 demo (switching it off brought the ~600 fps cap straight back), and no slowdown in the AIO Graphics Test on any API. ⚠️ This exact build has not yet had a real DirectX 12 game run through it. Please report DirectX 12 games, with fps before and after.

## 🔧 Smaller

- The Wayland slide deck gained a results slide: 28 September speeds against the original Wayland tests.

## ⚠️ Carried over — still open

- **Wayland:**
  - In the AIO Graphics Test, Wayland still trails X11 by about 8% on its DirectX 12 test and about 14% on DirectX 10, while it leads on OpenGL, DirectX 11 and DirectDraw. A normal DirectX 12 program runs faster on Wayland, so this may only affect that test. It's being looked into.
  - OpenGL, DirectX 9, 8 and DirectDraw on Wayland top out around twice the screen's refresh rate in uncapped tests.
  - Mali, Xclipse and PowerVR through the adapter need testers.
- Everything listed as open in 3.1.3 is unchanged: the Linux Steam client items (FlatOut after Resume, Team Fortress 2 "insecure", Guide pressed twice after sleep, the proot patches' A/B), the Fusion HUD's GPU usage with **Lock GPU to max clock**, and BannerHub signing Steam out of SteamLite games.
