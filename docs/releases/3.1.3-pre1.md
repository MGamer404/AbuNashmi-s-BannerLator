# Bannerlator 3.1.3 — pre-release 1

Run Windows apps and games on Android — no PC and no root required.

> ⬆️ **Upgrading from the September 21 test build (the action-run APK)?** Two steps, nothing to re-download:
>
> 1. Install this APK **over** your current install — your data is kept.
> 2. Open **Contents → Linux Runtime** once. In that build the Steam (Linux) entry lived inside a Wine container; it now has its own settings and no container. Opening that tab moves your entry out of the container and carries its settings (HUD, LSFG, audio, drivers) over.
>
> Then launch **Steam (Linux)** from the games list as before. You stay signed in; your games, Valve's ARM64 Proton and your downloads are all still there. Do **not** remove or re-download the runtime. If you made a container only for Steam and nothing else lives in it, you can delete it afterwards (the *Linux Desktop* entry stays in the container). If you skip step 2 the old entry still launches, but with the container's settings until you open the tab.
>
> **In-app updates:** stable users are never offered a pre-release. Testers who turn on **Settings → Include pre-releases** are offered this one (versionCode 87).

**Pre-release 1 of 3.1.3 adds Valve's own Steam client — the real Linux one, built for ARM64 — running inside Bannerlator.** Sign in, install a game from your library, and play it: the client downloads the game, Valve's ARM64 Proton runs it, and the Turnip driver draws it. No Wine container is involved, and nothing about your existing containers changes.

- **The Steam client itself:** Big Picture with a controller, or the desktop UI. Your library, the store, downloads, cloud saves, friends and chat, the overlay, the shader pre-cache — it is Steam.
- **A first run that takes care of itself:** the client downloads, updates and restarts once by itself; the compatibility layer is fetched right after you sign in and the client restarts once more when it lands. From then on every game you install runs through it with nothing to pick.
- **Proven games** (AYANEO Pocket FIT, Adreno 750): Half-Life 2, Portal 2, Team Fortress 2, Half-Life, GTA V (Legacy), Need for Speed Most Wanted and Payback, FlatOut 1 and 2, Brawlhalla, DiRT Showdown.
- **Sound and voice:** games use DirectAudio, and the client's microphone works (proven in Steam's voice tester).
- **Controllers:** the client sees a real Xbox 360 pad, including the Steam button; the on-screen pad appears when there is none.

Everything from 3.1.2 (the Wayland backend) is here too.

| File | What it is |

| `Bannerlator-3.1.3-pre1-standard.apk` | the normal app (`com.winlator.banner`) |
| `Bannerlator-3.1.3-pre1-pubg.apk` | the "pubg" package name flavour (`com.tencent.ig`) |

The Linux runtime itself (about 755 MB) is **not** in the APK — the app downloads it once, see Setup. Valve's ARM64 Proton (about 2 GB) is downloaded by the Steam client on your first sign-in.

# Setup

1. Install the APK for your flavour over your current install (data is kept), or fresh.
2. Android **Settings → Developer options → Disable child process restrictions → on.** (If you do not see Developer options, tap *Build number* seven times in *About phone*.)
3. In the app: **Contents → Linux Runtime → Download.** One download, about 755 MB. When it finishes, a **Steam (Linux)** entry appears in your games list.
4. Launch **Steam (Linux)**. The first run shows a loading screen while the client downloads itself and updates (a few minutes; the clock on the screen tells you it is alive). Sign in with your Steam account (the QR code and the Steam mobile app work).
5. **Wait here — do not install a game yet.** The client fetches Valve's ARM64 Proton by itself, but it may not start on its own: watch for the **Proton Experimental (ARM64)** install box (about 2 GB) and, if the phone has an SD card, **choose internal storage or the card** and tap *Install*. If nothing appears, look in **Downloads** — it may be waiting on that choice.
6. **Let it restart itself.** When that download finishes the client restarts on its own — the loading screen comes back with "Steam is restarting once…" and goes away when Steam is back, still signed in. A game installed *before* that restart gets Steam's own tool chain (~1.7 GB it cannot use) and fails to launch with no error, so wait it out.
7. **After the restart:** install a game from your library and play it. That's it — nothing to pick.

**Optional:**
- The ⚙️ next to the Steam (Linux) entry has its settings: resolution (720p by default — the client's interface is the most expensive thing a session draws), the **draw driver** (the Turnip that draws the client and its games) and the **display driver** (the one that puts frames on your screen), core lists for the client and for games, DirectAudio, frame generation and the HUD.
- Other Turnips for drawing: **Contents → Drivers → import** one of the `-Linux.zip` builds from [Banners-Turnip](https://github.com/The412Banner/Banners-Turnip/releases) (there are plain, A8xx and 710/720 builds). The runtime ships one already; import only if you want to compare.
- **GE-Proton and proton-cachyos (ARM64 builds)** can be downloaded in **Contents → Linux Runtime** and chosen per game in the client's own *Compatibility* page. A game's per-game choice follows Steam's rules, not the app's.

### 🆕 New here? Installing for the first time

**Before you start — check two things:**

- **Your phone needs an Adreno GPU** (Snapdragon). Mali, Xclipse and PowerVR phones will get sound over a black screen. There is no warning for this yet, so please do not install it to "see what happens".
- **Turn on one Android setting first:** go to **Settings → Developer options → Disable child process restrictions** and switch it **on**. Do not see Developer options? Go to **Settings → About phone** and tap **Build number** seven times, then it appears.
  Without this switch, Android randomly kills the Steam client and your session just dies for no visible reason. Some phones do not have the switch at all — on those, this build will not work yet.

**Then:**

1. **Download and install the APK.** There are three — just take **standard** unless you specifically use the pubg or ludashi build already.
2. **Open the app and go to Contents → Linux Runtime → Download.** This is about **755 MB**, once. It is not in the APK, so this step is required.
3. When it finishes, a **Steam (Linux)** entry appears in your games list. **Tap it.**
4. **First launch takes a few minutes.** You will see a loading screen — Steam is downloading and updating itself. There is a clock on screen so you know it is alive. It may restart itself once; that is normal.
5. **Sign in** with your Steam account. Password, or the QR code with the Steam mobile app — both work.
6. **⏳ Now wait. Do not install a game yet — this is the part people get wrong.**

   Steam fetches Valve's ARM64 Proton by itself. **It may not start downloading on its own** — watch for an install box for **Proton Experimental (ARM64)** (about 2 GB). If your phone has an SD card, Steam will ask **where to put it: internal storage or the SD card**. Pick one and tap **Install**. If nothing appears, check the **Downloads** page — it may be sitting there waiting on that choice.

   **When the download finishes, still do not touch anything.** The loading screen comes back saying **"Steam is restarting once…"** — **the client restarts itself automatically.** That restart is what makes every game you install run properly. Let it happen; Steam reopens on its own, still signed in.

   ⚠️ **Installing a game before that restart breaks it.** Steam grabs the wrong set of tools — about 1.7 GB you will never use — and the game just fails to launch with no error message. Wait for the restart. It is a minute or two.
7. **Once Steam has come back on its own — now install a game from your library and play it.** Nothing to configure, nothing to pick.

**That's it.** Your existing Wine containers and games are completely untouched by any of this.

**Optional tweaks** — the ⚙️ next to the Steam (Linux) entry has resolution (720p by default, because Steam's own interface is expensive to draw), drivers, audio, frame generation and the HUD.

# What's New — everything since 3.1.2

## 🐧 The Linux Steam client

Valve ships a native ARM64 Linux Steam client. Bannerlator now runs it, inside a small Arch Linux ARM root filesystem, under Valve's **gamescope** compositor, on top of the same embedded Wayland compositor 3.1.2 introduced. What that means in practice:

- ✅ **It is the real client:** sign-in (password, QR, Steam Guard), the library, the store, downloads with Steam's own resume and verification, cloud saves, the overlay, friends and chat, Big Picture and the desktop UI, controller configuration, the shader pre-cache.
- ✅ **Games run through Valve's ARM64 Proton** (the depot the client downloads, wrapped as a *Bannerlator Proton (ARM64)* compatibility tool that runs it without the Linux runtime container Android cannot provide). Wine, DXVK, VKD3D and FEX are Valve's own, matched to each other. Only the Turnip driver is ours.
- ✅ **No container.** The client has its own settings entry; no Wine prefix is created or touched. Your existing containers, games and shortcuts behave exactly as before.
- ✅ **Your games in one place:** the app's own game folders (phone and card) are the client's library folders, so a game the app installed shows up installed in the client, a game the client installs lands where the app would have put it, and nothing is ever copied. Uninstalling in the client releases it in the app.
- ✅ **The account's owned games and the anti-cheat runtimes** (BattlEye, EAC) are mapped to the ARM64 tool before the client can reach for anything x86.
- ⚠️ **First-run window:** a game installed in the couple of minutes while Valve's ARM64 Proton is still downloading gets Steam's own tool chain assigned for that session (about 1.7 GB of downloads it then cannot use). The automatic restart when the layer lands fixes the assignment; the extra download stays. Launching a game in that window fails quietly. After the restart there is no window.

## 🧭 A first run that takes care of itself

Tested from a clean install, start to finish, and each of these was a real problem on the way:
- ✅ **Loading screen** until the client draws its first frame: the runtime's milestone, the client's own download percentage, a clock, and a rotating hint. It comes back for the client's self-update restart and for the compatibility-layer restart, and leaves on the first frame — the picture arrives with Steam's start-up chime, not five seconds after it.
- ✅ **The compatibility layer is fetched after you sign in,** not before (a signed-out client silently drops the request). When it lands, the client restarts itself once so everything installed before or after that point runs through it.
- ✅ **A fresh install starts on Turnip.** The old default was the proprietary driver, which cannot share frames with the compositor: sound over a black screen for every new user.
- ✅ **Opening the Steam (Linux) settings no longer crashes** on a fresh install (its entry has no Wine, Box64 or FEX to speak of, and the editor assumed it did).
- ✅ A session that dies before the client ever draws shows its exit status and log folder for a moment instead of a flash of black.

## 🔊 DirectAudio, and a microphone

- ✅ Games in the client use **DirectAudio** (the same low-latency Android path Wine games use), chosen in the entry's settings.
- ✅ The Steam client gets an input device — **DirectAudioMic** — with a working voice slider, proven in Steam's own voice tester. Five separate faults sat behind "no input device"; they are all gone.
- ⚠️ In-game voice chat with real people has not been tested yet.

## 🎮 Controllers and input

- ✅ The client sees a **real Xbox 360 controller** (an evdev device the app feeds), including the **Steam button**, so Big Picture, the overlay and Steam Input work as on a PC. The on-screen pad appears when no controller is connected.
- ✅ The client has its own input interposer instead of sharing Wine's.
- ✅ **Wayland:** real **multi-touch** (`wl_touch`) instead of a synthesised mouse; the guest's real cursor and its hide requests are honoured; the overlay pointer hides when idle or when a controller is driving; the soft keyboard types capitals and shifted symbols.
- ⚠️ The Steam Controller puck is still untested (carried over).

## 🖼️ Drivers

- ✅ **Three kinds of Turnip now, and the app knows which is which.** The regular Android driver puts frames on the screen; the *-Wayland* builds draw Wine games on Wayland; the new **-Linux** builds (glibc) draw the Steam client and its games. [Banners-Turnip](https://github.com/The412Banner/Banners-Turnip) builds all three, and the importer sends each zip to the list that can actually load it — no more "imported, but not offered".
- ✅ The Steam (Linux) entry has a **draw driver** row (the Linux Turnip) beside the **display driver** (the Android Turnip), each explained in place.
- ✅ Turnip stops advertising present timing without calibrated timestamps (a crash source on the client's path).

## ⚙️ Cores, refresh, resolution

- ✅ The client gets **all eight cores**; Steam pins its own interface renderer to five by default, which is right on a PC with a game running and wrong when the client is all there is. Games get their own core list, separately.
- ✅ Sessions run at the **screen's highest refresh rate**, never the frame cap.
- ✅ **720p** by default for the client (its interface is the most expensive thing a session draws); change it in the entry's settings.

## 📚 Library, storage, downloads

- ✅ Two libraries — internal storage and the card — presented to the client as its own library folders; downloads land on the card when you choose it; free space is the library's, not the phone's.
- ✅ Installs the client made are adopted by the app's store database (size from the manifest, the build the client put there); an uninstall in the client releases the game; a stale prefix link is recovered instead of hiding a game.
- ✅ Shared redistributables are marked as already run in every prefix, including one the client creates mid-session — no x86 installers starting under emulation and hanging a first launch.

## 📝 Logs

- ✅ **One folder per session** in `Download/Bannerlator-LinuxSteam/session-<date>/`: the session log (proot, gamescope, the client's own output), a device report, a network report, controller diagnostics, the audio daemon's log, Android's crash buffer as it stood when the session ended, and the client's own logs.
- ✅ The client's logs are **scrubbed** before they are copied: session tokens, GUIDs, Web API keys and Steam IDs are masked; `loginusers.vdf`, `config.vdf` and the `ssfn` files are never copied. A log bundle is safe to post.
- ✅ Collection happens on the close path, cheap pieces first, so it finishes before the session is torn down.

## 🛠️ Smaller

- ✅ The in-game drawer and the HUD describe a Linux session as what it is (its own graphics API, not the container's leftovers).
- ✅ A NetworkManager stand-in answers the client's connection questions (Settings → Internet no longer breaks).
- ✅ GStreamer plugin libraries Proton needs are shipped; a competing Steam client on the device is named before the session starts and stopped, since it takes the account's session.
- ✅ The seccomp probe that could kill a session for its own reasons is gone.
- ✅ CI bounds the informational unit-test step (it hung a build for 25 minutes once).
- ✅ Three session fixes ported from WinNative (maxjivi05, `feature/wayland-gamescope`): sessions that never started, black ones, and the network stand-in.

# What it can and cannot do right now

**Can:**
- **Steam:** sign in, browse, install, update, verify, cloud-sync and play games from your library, with the overlay, Big Picture or the desktop UI, on a controller or on the touch screen.
- **Games:** the Source titles, GTA V (Legacy), NFS Most Wanted and Payback, FlatOut 1 and 2, Brawlhalla, DiRT Showdown — playing, on one device.
- **Sound:** DirectAudio for games, a microphone for the client.
- **Drivers:** pick the drawing Turnip per entry; import Linux builds from Banners-Turnip.
- **Also:** frame generation, screen effects and the HUD on the client's sessions, session log bundles you can post.

**Cannot yet, or not proven:**
- **Mali, Xclipse and PowerVR:** nothing. The runtime's driver is Turnip.
- **Phones without the "Disable child process restrictions" switch:** the session is killed at random. A detect-and-warn card and a one-tap fix (root / Shizuku) are the next thing to build.
- **GTA V Enhanced** does not run (a null call in x86 code under FEX, ~2 minutes in). **Serious Sam Shatterverse** is killed by Android for memory during its shader burst. **NFS Hot Pursuit Remastered** faults inside FEX.
- **TF2 "insecure"** — open, see above.
- **Voice chat with people** — untested. **Remote Play, streaming, family sharing** — untested.
- **Join-a-friend / invites** — built, not proven.
- **Steam Controller** — untested.
- **The client's desktop session** (the *Linux Desktop* entry) has had far less testing than Big Picture.
- Leaving the app pauses the session; come back and it resumes. That is by design.

# Coming in later pre-releases — your other games inside the Steam client

None of this is in pre-release 1; it is the next line of work, in this order:

1. **Custom games in the client's library.** The games Bannerlator already runs in its Wine containers — your own installs and shortcuts — added to the Linux Steam client's library as non-Steam games, with their artwork, so the client is one place to launch everything. Launching one hands it to the app's container, not to Valve's Proton.
2. **GOG, Epic and Amazon games in the same list.** The titles the app's store pages installed from GOG, the Epic Games Store and Amazon Games appear in the client as custom games too, launched through the app the same way, with their store's own sign-in and cloud saves staying with the app.
3. **The other way round:** a game installed by the Linux client showing up in the app's library with the same artwork and per-game settings it has today (the library sync already covers Steam installs; the store pages will follow).
4. **Client updates from the app,** a logs manager for the session folders, and touch tap accuracy in Big Picture.

# What is left — fixes and performance

1. **The process-limit switch:** detect it, warn, and flip it with root or Shizuku when the phone allows.
2. **A gate for non-Adreno phones,** so the entry says why instead of going black.
3. **The first-run window:** keep Steam's own tool chain from being pulled in when a game is installed before the layer lands.
4. **TF2 secure status:** connect to a real secure server with `-condebug` and let the game say why.
5. **A tester matrix beyond one device:** Adreno 830/840 phones, Thor, and the phones that reported black screens.
6. **Performance:** the client's own interface costs frames when a game is running; measure and trim.
7. The list above: custom games, then GOG / Epic / Amazon titles, in the client's library.

# Logs, if something goes wrong

- `Download/Bannerlator-LinuxSteam/session-<date>-<time>/` — the whole session: `session.log` (proot, gamescope, the client's output), `device.txt`, `network.txt`, `fake-input.txt` (controllers), `audio.log`, `crash.log` (Android's crash buffer), and `steam/` with the client's own scrubbed logs.
- `Download/Wayland-logs/wayland-<date>_<time>.log` — the compositor: the driver it loaded, windows, frames on screen per 10 s.
- Post the whole session folder; it is scrubbed for that purpose.
